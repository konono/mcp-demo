> 作業タイトル: 公開 API 検索デモスクリプト + opencode Skill の作成
> 完了日時: 2026-10-06

## 何をやったか

空のディレクトリから、公開 API 4 種（Wikipedia / Hacker News / GitHub / Stack Overflow）を
横断検索する Python CLI と、opencode 用の SKILL.md、README を作成した。
全ソースの実動作を確認し、HTML エンティティ混入のバグを 1 件修正した。

## うまくいったこと

- **依存ゼロの方針**: 環境に Python が無いことを最初に確認したのが、標準ライブラリのみという判断につながった。結果として「叩けば動く」デモになった。
- **先に実行して確かめた**: API のレスポンス構造を仕様の記憶に頼らず実際に叩いたので、エスケープ問題を早期に発見できた。
- **失敗を errors に逃がす設計**: レート制限の厳しい GitHub を含めても、デモが全滅しない構造にできた。

## うまくいかなかったこと / 反省

- `strip_html()` を自作した時点で、HTML 断片なのだからエンティティも来る、と想定できたはず。タグ除去とアンエスケープはセットで考えるべきだった。
- Stack Overflow の title のエスケープには、修正のついでに気付いた形だった。最初に全ソースの全フィールドを見て回る習慣があれば一度で済んだ。

## 学び

- **外部 API のテキストフィールドは HTML 断片を疑う**。特に検索系 API の snippet/highlight はマッチ箇所を `<span>` で囲んで返すことが多く、同時に実体参照も含む。
- **エージェント向け CLI の設計原則**: ①依存ゼロで即実行 ②既定 JSON ③部分失敗を可視化して処理継続 ④`description` に「いつ使うか」を書く。これらはこのスクリプトに限らず再利用できる。
- **Skill の価値は実行可能なスクリプトそのものより、使い分けの指針にある**。SKILL.md にソースごとの選び方とレート制限の注意を書いたことが、単なる `--help` との差分になっている。
