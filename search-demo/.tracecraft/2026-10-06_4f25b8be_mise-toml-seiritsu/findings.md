## Finding 1: Issue 2 の真因は Python 不在ではなく mise.toml への未登録

### 調べた理由
前セッション (dd86561f) の Issue 2 で `mise x -- python` が失敗した原因を「uv が取得した CPython は mise から見えない」と結論づけていた。Python を追加する際に、ダウンロードが必要かどうかで真因が切り分けられる。

### 調査方法
`mise use python@3.12` を実行し、インストール処理が発生するかを観察した。

### わかった事実
- `python@3.12.15` は `already installed` と表示され、ダウンロードは発生しなかった
- つまりマシン上には元から CPython 3.12.15 が存在していた
- 失敗していたのは、プロジェクトにもグローバルにも「どのバージョンを使うか」の設定が無かったためだけだった

### 根拠
- `mise use python@3.12` の出力 `mise ⇢ python@3.12.15  1ms · already installed` および `installed 0 tools · 1 already installed in 3ms`
- 前セッションのエラーメッセージ自体が `Set a global default version with one of the following: mise use -g python@3.12.15` と具体バージョンを提示していた。これは mise が 3.12.15 の存在を認識していたことを示す。

### 作業への影響
Python 追加のコストがゼロ（ダウンロード不要）だったため、Decision 3 で据え置いた判断を覆すハードルが低かった。

### 未確認事項
- この CPython 3.12.15 がいつ・何によってインストールされたものかは未確認

## Finding 2: python と uv でバージョン固定の粒度を変える妥当性

### 調べた理由
「より正確」にするにあたり、どのツールをどの粒度で固定すべきかを決める必要があった。

### 調査方法
実際にインストールされているバージョンを `--version` で確認し、各ツールがプロジェクトに与える影響範囲を比較した。

### わかった事実
- 実バージョンは `Python 3.12.15`、`uv 0.12.23 (aarch64-unknown-linux-gnu)`
- pyproject.toml の制約は `requires-python = ">=3.10"` であり、3.12 系であればパッチレベルは問わない
- uv はビルドバックエンドの呼び出しと成果物生成を担うため、挙動差が成果物に直結する

### 根拠
- `mise x -- python --version` → `Python 3.12.15`
- `mise x -- uv --version` → `uv 0.12.23 (aarch64-unknown-linux-gnu)`
- `/Users/kono/gitrepo/mcp-demo/search-demo/pyproject.toml` の `requires-python = ">=3.10"`

### 作業への影響
`python = "3.12"`（マイナーまで）、`uv = "0.12.23"`（パッチまで固定）という非対称な指定にした。

### 未確認事項
- uv のバージョン差で実際に成果物が変わるケースを検証したわけではない。固定は予防的措置。
